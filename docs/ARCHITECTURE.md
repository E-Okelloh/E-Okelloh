# GPOS Architecture

Systems description of the E-Okelloh profile. Component-level specification lives in
`docs/COMPONENTS.md`; the governing design system lives in `docs/DESIGN.md`;
the engineering contract lives in `docs/ENGINEERING_SPECIFICATION.md` and is
authoritative for how assets are built.

---

## Data Flow

```
GitHub API
   │
   ├───────────────► .github/workflows/metrics.yml ──► .github/scripts/generate-metrics.sh
   │                          (schedule: daily 06:00 UTC)              │
   │                                                                   ▼
   │                                                         metrics/*.svg  (rewritten)
   │
   ├───────────────► .github/workflows/snake.yml ──► Platane/snk ──► assets/snake.svg
   │                          (schedule: daily 00:00 UTC)
   │
   ├───────────────► .github/workflows/update.yml ──► assets/dashboard.svg (LAST SYNC stamp)
   │                          (schedule: weekly)
   │
   ▼
README.md  ── assembles ──►  dashboard + metrics widgets + terminal + footer + dividers
```

The README is a thin composition layer. It fetches nothing, computes nothing, and
styles nothing. The compound `dashboard.svg` carries the first five modules
(Header → Capabilities); the GitHub-generated widgets carry the live metrics; Git
API feeds the snake; `terminal.svg`, `divider.svg` and `footer.svg` complete the
composition.

## Asset Lifecycle

### Static assets (`assets/`)

Hand-authored, committed once, refined deliberately. Every file is documented
(component comment header), token-based (`:root` CSS custom properties), responsive
(`preserveAspectRatio="xMidYMid meet"`) and motion-scoped per the engineering
contract (§ Motion Principles).

### Generated assets (`assets/snake.svg`, `metrics/*.svg`)

Committed as source-of-truth files; regenerated by CI on schedule:

| Workflow | Schedule | Output | Postcondition |
|----------|----------|--------|---------------|
| `snake.yml` | daily `00:00 UTC` | `assets/snake.svg` | commit & push only if changed |
| `metrics.yml` | daily `06:00 UTC` | three `metrics/*.svg` panels | commit & push only if changed |
| `update.yml` | weekly `06:15 UTC` | `LAST SYNC` stamp inside `assets/dashboard.svg` | commit & push only if changed |

Workflows require `contents: write`. All writes go to the default branch.

### Why local images instead of third-party README stats?

- Zero third-party requests while viewing the profile.
- No external service outage breaks the profile.
- Full control of palette, type, and layout — the design system is enforced.

The single remaining external request is the contribution graph service; it honors
the dashboard aesthetic via theme tokens, and no local equivalent exists without a
full contribution-rendering implementation.

## Engineering Contract (summary of `docs/ENGINEERING_SPECIFICATION.md`)

- Every SVG: `title`, `desc`, `viewBox`, `role="img"`, `preserveAspectRatio`, semantic grouping, component comment header.
- Layer order: defs → background → panels → connections → animations → labels → foreground.
- Colors via CSS custom properties in the `:root` block. Only language-identity dots may hold a canonical hex.
- Motion: packets 2–4s `ease-in-out`, pulses 3–5s, cursor 700ms, fades 250ms; node scale within 3%.
- Naming: `dashboard-root`, `network-node`, `status-indicator`, `terminal-root`, `footer-root`, …; classes `panel divider label node connection packet metric`.

## Regeneration

Do not hand-edit `metrics/*.svg`. Edit `generate-metrics.sh` and run:

```sh
bash .github/scripts/generate-metrics.sh
```

The script reads the GitHub API for `GITHUB_REPOSITORY_OWNER` (default `E-Okelloh`),
regenerates the three panels, and prints a confirmation. Set `GH_TOKEN` when running
outside CI to avoid the unauthenticated rate limit.

---

## Escaping & Text Rules (data panels)

- Escapes API strings via `esc()`: `&` `<` `>` `"` → entities.
- Truncate descriptions to 66 characters.
- Forked repositories are always excluded via `select(.fork | not)`.
- Language `null` becomes `OTHER`; totals come from `lang_total`.

## Change Process

### Add or modify a component

1. Justify against `docs/COMPONENTS.md`; no unspec'd modules.
2. Implement in the owning asset (dashboard/terminal/footer) or in the generator.
3. Validate: `xmllint --noout *.svg`, `bash -n .github/scripts/*.sh`, YAML parse for workflows.
4. Reference from `README.md` in the composed order.

### Change the design system

Run the change through the three points of truth concurrently: `DESIGN.md` (token/rule),
`COMPONENTS.md` (component spec), `STYLE_GUIDE.md` (mapping). Do not let them diverge.

## Accessibility

Any information-only color pairing is accompanied by text. All SVGs ship `title`,
`desc`, `role="img"`, `aria-labelledby` and a full-canvas high-contrast background.
Behavior must be comprehensible with animations disabled (Definition of Done,
`DESIGN.md §17`).

---

## Security

- No secrets committed; CI expects only the auto-scoped `GITHUB_TOKEN`
  (`contents: write`).
- Remote content is limited to GitHub API JSON through the single
  `generate-metrics.sh` pipeline with entity escaping.
- No JavaScript anywhere, eliminating the XSS surface of the profile.
